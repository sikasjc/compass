# Compass 使用手册

Compass 是本地运行的 A 股研究工具。当前主导航依次为：开始、今日信号、账户、策略回测、策略实验室、行情数据、标的池、设置、日志。策略实验室内部还包含规则编辑、信号预览、验证发布和经典模板/参数调优页面。

## 1. 推荐使用顺序

1. 在“标的池”加入需要研究的上证或深证指数、ETF；
2. 在“行情数据”完成增量同步并检查区间、行数和质量状态；
3. 在“策略实验室”选择经典模板，或创建自定义规则策略；
4. 在“策略回测”组合多个策略和多个 ETF，检查收益、回撤、成交、费用和比较基准；
5. 在“账户”创建账户并维护现金、真实持仓和持仓快照；
6. 在“今日信号”选择账户与已发布策略，生成最新完整交易日的调仓建议；
7. 采用、忽略或记录实际执行结果，在账户页复盘采用建议与不采用的差异。

## 2. 标的池

系统只维护一个关注标的池。先选择上证或深证市场，再输入六位代码；支持换行、逗号或空格分隔。快捷分类可以追加常见指数，代码后的灰色中文名称用于辅助核对。

页面会汇总关注标的数、数据就绪数和缺失数，并在每个标的后显示本地行情区间。单个标的可直接同步；删除关注不会自动删除已保存行情，需要在行情数据页单独清理。

## 3. 行情数据

支持近 2 年、5 年、10 年和自定义区间，可以增量同步全部、只同步缺失标的或重试单个标的。同步按标的并发执行，但每个标的独立保存：部分失败不会回滚其他成功数据。

任务历史展示来源、区间、提交和结束时间、标的级进度、成功数量及错误原因。进行中任务可以终止但不能清理；已结束任务可以分页浏览和清理。

质量提示要区分：

- “现有数据区间内连续”表示已保存首尾日期之间没有内部断档；
- “较早历史未覆盖”表示目标区间早于该标的当前首日，并不等于已有数据损坏；
- 数据源没有返回的停牌日、上市前日期或非交易日不应视为行情缺口。

每个标的只保留一份当前行情。清理单个标的或全部行情是不可逆操作，任务历史不会因此自动删除。

## 4. 数据源与网络

行情采用固定回退顺序：腾讯证券 → 东方财富 → BaoStock。腾讯证券作为推荐主源；东方财富通过 AKShare 适配，但界面展示实际网站来源，不把适配库名称当作数据源。

设置页支持不使用代理、系统代理和自定义代理 IP/端口，并可分别测试代理、腾讯证券、东方财富和 BaoStock。HTTP 请求超时可配置；BaoStock 是会话式 TCP 接口，按串行方式使用。

连接失败时按以下顺序检查：设置页连接测试 → 日志页脱敏请求摘要 → 代理软件规则 → 系统防火墙。普通行情代理设置和安装 PyTorch 的命令行代理互相独立。

## 5. 策略实验室

策略实验室管理策略定义，不运行账户回测。策略库区分可反复保存的本地草稿和不可变的已发布版本；复制、停用和删除使用图标操作。账户和今日信号只引用已发布版本，修改草稿不会悄悄改变既有信号。

### 经典模板

目前包含买入持有、双均线、横截面动量、ETF 轮动、RSI/布林均值回归、自定义规则 DSL 和 Kronos K 线预测等定义。模板卡片会说明原理、适用场景和主要风险。

### 自定义规则

规则编辑器按“信号 → 动作 → 执行时间”组织条件，支持调整到目标仓位、增加仓位、减仓到指定比例、全部卖出和保持仓位。条件除行情字段和技术指标外，还可使用 `has_position`、`holding_days`、`position_return`、`position_drawdown`。规则按优先级执行，信号预览会展示最终命中的规则和目标仓位；规则保存为受限 AST/DSL，不执行任意 Python `eval`。

标准流程是：创建草稿 → 编辑规则与变量 → 信号预览 → 验证与发布。预览只检查历史命中和目标仓位变化，不代表收益；收益与比较基准仍在策略回测中查看。

收盘后才能确认的日线信号，最早在下一交易日成交。系统不会允许使用完整当日收盘价产生信号后再按同一收盘价成交。

### 参数实验

参数实验按时间顺序切分为 40% 基础训练、40% 三段连续滚动验证和 20% 冻结测试。结果表会逐段展示三个窗口的收益，并以中位数汇总；稳健评分会扣除不同窗口间的标准差，且至少两个验证窗口必须有成交。只有稳健评分第一的候选才查看冻结测试。训练收益高不表示可用；应同时检查验证收益、稳健评分、验证 Calmar、最差回撤、成交次数和冻结测试稳定性。

当前可选择三类已发布模板作为调优起点：

- 双均线：搜索短均线、长均线和确认天数；
- 自定义规则 DSL：搜索变量中标记为“参与优化”的导出变量，候选值必须位于变量定义范围内；
- Kronos：搜索买入/退出阈值、正向路径比例、趋势窗口和重算间隔。模型规模、采样参数和预测周期保持模板值，避免一次实验同时改变模型与仓位规则。

所有候选组合最多 50 组。每组候选会运行一次基础训练和三个验证窗口，因此实验次数约为参数组数的四倍，最后再单独运行一次冻结测试。Kronos 会复用相同模型输入的预测缓存，因此调整阈值和趋势过滤通常不需要重复推理；改变重算间隔会改变预测日期，仍可能产生新的模型计算。发布最佳候选会创建新的不可变策略版本，不会修改原模板。冻结测试如果被反复用于修改策略，就不再是“未见数据”，应创建新的时间区间继续验证。

## 6. Kronos 策略

Kronos 根据最近一段 OHLCVA 日线预测未来 K 线路径，Compass 再用预测收益、正向路径比例、趋势过滤、排名和持仓上限转换为目标仓位。它可以和传统策略共同持有多个 ETF。相同模型、输入窗口和采样参数的推理结果会在当前进程内使用有界缓存，修改入场/退出等仓位规则时不需要重复执行相同推理。

首次建议使用 `mini`、历史 256 日、预测 5 日、每 5 日重算。模型输出不是确定收益；严格样本外回测前要确认模型预训练数据截止日期，并计入佣金、滑点和采样不确定性。

回测结果中的“预测质量”会把每次预测和预测周期末的真实收盘收益对齐，同时计算从下一可执行价格到周期末收盘的可交易收益。预测区间尚未结束的尾部记录不会参与统计。方向命中率、预测与实际收益相关性、全体标的和入选标的平均可交易收益应结合成交费用、样本数量和不同市场阶段一起判断，不能单独当作收益保证。

安装方式：

```powershell
# Windows NVIDIA GPU；代理仅影响本次安装
.\scripts\install-kronos.ps1 -Mode CUDA -Proxy http://127.0.0.1:7897 -IncludeDev
```

```bash
# CPU / macOS / Linux 通用
uv sync --extra kronos
```

安装后策略表单会显示 PyTorch、CUDA 和设备状态。“自动”会依次选择 CUDA、Apple MPS 或 CPU。模型首次使用时从 Hugging Face 下载并缓存；`HF_HOME` 可改变缓存位置，`HF_ENDPOINT` 可配置镜像。

## 7. 策略回测

策略回测共享一个账户，多个策略分别给出 ETF 目标仓位，再按各自资金占比合并。支持空仓或自定义初始现金/持仓、佣金、最低佣金、滑点、再平衡方式、仓位偏离阈值和最小交易金额。

回测结果默认不自动加载；在任务历史点击“查看结果”后加载并缓存。图表支持缩放，`B`/`S` 表示买入/卖出。比较基准在结果图表处选择，不属于账户成交参数。

Kronos 回测可能远慢于传统指标策略。先用少量 ETF、较短区间、`mini` 模型和较大的重算间隔验证流程，再扩大实验。

## 8. 账户

账户页负责新建、删除账户方案，配置现金和持仓，并查看资金与仓位变化。多个账户可以引用同一份共享持仓，也可以维护独立持仓；共享可避免重复录入，但修改共享持仓会影响所有引用账户的当前状态。

持仓保存会形成去重快照。历史快照只读，可以载入后编辑并另存为新状态。持仓数量和现金只在保存持仓或记录成交时变化；资金图表会在这些事件之间使用本地每日收盘行情连续盯市，因此增量同步新行情后，账户净值、持仓市值、现价和浮动盈亏会随之更新，但不会额外生成重复持仓快照。页面会显示估值日期；持仓缺少最新行情时会明确提示并暂用快照价格。

ETF 和指数会按宽基、行业、红利、成长科技、债券、商品、海外或其他自动归类，并尽量从已同步中文名称识别更细的主题。资金曲线按类别拆分持仓市值，当前持仓区同时提供类别占比和标的明细。该分类用于组合观察，不替代基金公司披露的正式分类；无法可靠识别时归入“其他”。

## 9. 今日信号与执行闭环

今日信号只展示账户当前持仓，不在这里编辑账户。选择账户和一个或多个已发布策略后，系统基于最新本地完整交易日生成目标仓位与调仓建议，并按策略分组解释对多个标的的操作依据。

信号会记录账户、策略版本、行情版本和交易日。策略、持仓或行情发生变化后，旧建议会标记失效；过期建议不能继续当作当前状态执行。

用户可以采用建议、忽略建议或记录实际成交。已采用或存在执行记录的信号属于审计链路，不能删除；只有未采用记录可清理。账户页可以试算“采用建议”和“完全不采用”在之后行情中的差异，但这属于事后情景比较，不是实盘收益承诺。

## 10. 自动任务、设置与日志

设置页支持应用启动时、固定间隔或收盘后自动增量同步。自动任务只创建行情同步任务，不会自动执行调仓建议。

日志位于独立页面，可按级别和关键词筛选。网络日志包含脱敏后的 HTTP 地址、操作、响应摘要或 BaoStock TCP 错误码；不会展示密码、令牌或未脱敏敏感内容，也不会补录功能启用前的旧请求。

## 11. 数据、备份和卸载

默认数据目录：Windows `%LOCALAPPDATA%\Compass`，macOS `~/Library/Application Support/Compass`，Linux `$XDG_DATA_HOME/compass` 或 `~/.local/share/compass`。设置页会显示实际路径；`COMPASS_DATA_DIR` 可以覆盖。

备份时先停止应用，再完整复制整个数据根目录，不要只复制 SQLite。删除代码仓库不会删除个人数据；同时删除数据目录才会移除行情、账户、信号、策略草稿、回测、实验和日志，且不可恢复。

更完整的安装、启动、更新、卸载、目录结构和开发架构说明见仓库根目录的 `README.md`。

## 12. 常见问题

- 页面打不开：确认启动终端仍在运行，访问根地址 `http://127.0.0.1:8080/`，端口占用时换端口。
- 行情提示未覆盖：先确认是内部断档还是上市前/较早历史，再查看标的级质量详情。
- 调仓建议日历不一致：先同步行情，确认账户引用的策略和持仓没有在建议生成后改变，再重新生成。
- Kronos 当前仅 CPU：运行 CUDA 安装脚本并确认最终输出 `CUDA available: True`；启动脚本会保留已经安装的可选环境。
- Kronos 模型下载失败：配置 `HF_ENDPOINT` 或代理，重跑会复用 Hugging Face 缓存。
