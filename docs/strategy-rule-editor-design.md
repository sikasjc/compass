# 自定义策略规则编辑器框架设计

## 目标

策略实验室使用一个规则编辑框创建策略模板。编辑器描述“何时产生什么信号、采取什么动作、何时执行”，回测、参数优化和将来的实盘模拟共享同一份已验证规则，不在不同页面重复实现策略逻辑。

第一版面向日线数据，支持多条买入、卖出和目标仓位规则；分钟级和盘中“当天执行”作为后续扩展。

## 编辑器形态

页面主体是一块支持语法高亮、自动补全和行号的规则编辑框，旁边提供三个辅助区：

- 信号库：价格、成交量、均线、RSI、涨停、跌停、持仓收益、持仓天数、日期等，可点击插入代码片段；
- 导出变量：设置变量当前值、类型、最小值、最大值、步长以及是否参与优化；
- 验证与预览：展示语法错误、需要的行情字段、最少历史长度、信号日期预览和可能的未来数据问题。

可视化控件只负责向编辑框插入规则或修改变量，不保存另一套隐藏配置。编辑框中的版本化文档是唯一事实来源。

## 规则文档

建议使用结构化、可读的规则 DSL，而不是把买入和卖出拆成两个固定输入框：

```text
strategy "涨跌停与趋势规则" {
  variable fast_window = 20 optimize [5, 40, 5]
  variable slow_window = 60 optimize [40, 200, 20]
  variable target = 0.50 optimize [0.20, 1.00, 0.10]

  rule "趋势买入" priority 100 {
    when cross_above(sma(close, fast_window), sma(close, slow_window))
         and not limit_up
    action buy target_weight target
    signal_at close
    execute next_open
  }

  rule "趋势卖出" priority 200 {
    when cross_below(sma(close, fast_window), sma(close, slow_window))
         or limit_down
    action sell all
    signal_at close
    execute next_open
  }
}
```

保存时解析为不可变 AST，并记录 DSL 版本、内容哈希、变量定义和所需数据字段。执行器只运行 AST，不使用 Python `eval`。

## 分层模型

### 信号

信号只回答条件是否成立，不直接下单：

- 行情：`close`、`open`、`high`、`low`、`volume`、`amount`；
- 指标：`sma`、`rsi`、`pct_change`、`highest`、`lowest`、上穿和下穿；
- 涨跌停：`limit_up`、`limit_down`、`sealed_limit_up`、`broken_limit_up`；
- 持仓：`has_position`、`holding_days`、`position_return`、`position_drawdown`；
- 日期：星期、月末、调仓日等。

涨跌停价格必须按证券当日规则、昨收和价格最小变动单位计算，不能简单使用固定 10%。封板、开板等盘中状态需要分钟线或逐笔数据；只有日线时只能提供明确标注的近似信号。

### 动作

动作与信号分离：

- `buy target_weight x`：把目标仓位调整到指定比例；
- `sell all`：目标仓位归零；
- `reduce_to x`：减仓到指定比例；
- `increase_by x`：在当前目标基础上增加比例；
- `hold`：保持当前目标；
- 后续扩展 `rebalance` 和做 T 的成对动作。

所有动作先转换为目标仓位，再交给现有组合分配器、风险规则和撮合器处理。策略不直接生成可执行订单。

### 时间

规则显式包含两个时间：

- `signal_at`：信号在开盘、盘中或收盘的哪个时点可知；
- `execute`：动作在当天或后续哪个交易时点执行。

第一版日线模式只开放：

- `close -> next_open`；
- `close -> next_close`。

“当天收盘信号、当天收盘成交”默认禁止，因为知道完整收盘价后再按同一价格成交属于未来数据。以后接入分钟线后，可以开放 `intraday -> same_day_next_bar`；接入带截止时间的集合竞价或 MOC 模型后，再单独实现合法的当天收盘执行。

“第二天”始终解释为下一交易日，不是下一自然日。停牌、涨跌停无法成交时，由撮合器继续拒绝或按策略配置处理有效期。

### 多规则冲突

同一标的同一时点可能命中多条规则，必须确定性合并：

1. 先按 `priority` 从高到低排序；
2. 同优先级默认卖出和风控规则优先于买入；
3. 每个策略袖套最终只产生一个目标仓位；
4. 多策略之间仍由组合分配器按预算合并；
5. 回测报告记录命中的规则 ID、原始信号、最终动作和被覆盖原因。

## 参数优化器接口

编辑器导出的变量是优化器的输入，DSL 执行器本身不负责搜索。优化任务应包含：

- 策略模板版本和变量搜索空间；
- 网格搜索、随机搜索，后续可增加贝叶斯优化；
- 年化收益、夏普率、Calmar 等目标指标；
- 最大回撤、换手率、成交次数等约束；
- 训练区间、验证区间和样本外区间；
- 最大组合数、并发度、随机种子、进度和停止状态。

优化结果保留每组变量、回测指标和失败原因。用户选择候选组合后，只把变量当前值带回普通回测；不能覆盖策略模板，也不能把训练区间最优结果直接视为可用策略。

## 实施顺序

1. 定义规则文档、AST、版本和错误位置，兼容现有买入/卖出表达式；
2. 用单编辑框替换固定条件表单，增加信号库、变量面板和即时验证；
3. 增加动作、执行时间和多规则冲突解析，接入现有日线回测；
4. 增加涨跌停与持仓状态信号，并在报告中展示规则命中轨迹；
5. 实现带样本外验证的参数优化任务；
6. 接入分钟行情后扩展盘中信号和合法的当天执行。
